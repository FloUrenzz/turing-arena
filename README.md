# Тьюринг-арена — локальный алгоритмический бот

Python 3.11, SQLite, только стандартная библиотека. Во время обработки нет интернета, LLM API, готовых языковых моделей и скачиваний. Текущая версия `arena v1` отделена от исторического spike.

## Запуск на Windows

Из корня репозитория:

```powershell
python -X utf8 main.py --chat
python -X utf8 main.py --ask "Почему после дождя иногда появляется радуга? Объясни простыми словами."
```

По умолчанию выдача планируется через 3–40 секунд от начала обработки: `clamp(3 + 0.12 * длина + случайное(-1,1),3,40)`. Вычисление входит в общий интервал. Внешний дедлайн сильнее ожидания. Ответ идёт в stdout; время и диагностика — в stderr.

Для разработки, без искусственной задержки и с объяснением выбора:

```powershell
python -X utf8 main.py --ask "Еду в Астану не зимой, а летом. Что взять?" --fast --json
```

`--fast` и `--json` не применяются к сценическому текстовому выводу. `--seed 42` воспроизводит вариативность; `--db путь` подключает совместимую локальную БД, не пересоздавая её. Новая сессия начинается без памяти прошлого процесса.

## Алгоритм

Лексический слой находит понятия и известные формы, включая короткие фразы. Ограниченное сопоставление основ помогает с некоторыми падежными окончаниями. Правила учитывают тип вопроса, событие, участника, отрицание, сезон и предыдущую реплику. Полные строки контрольных вопросов не являются ключами маршрутизации.

Содержание берётся из фактов и коротких смысловых частей в SQLite. Объяснение явления, практический совет и социальная реакция имеют разные планы. Сборка использует доступные формы слов, сохраняет предпочтения персонажа, проверяет окончательный текст. В --json видны понятия, использованные факты и условия выбора.

Обработка выполняется в отдельном Windows-compatible spawn процессе с лимитом 2 секунды. Ошибка или зависание дают русский резерв. Родитель управляет задержкой и выдачей. Память применяется после успешной передачи; тот же request_id не генерирует новый вариант. Для внешнего sink при частичном побочном эффекте с ошибкой требуется идемпотентность/подтверждение получателя.

## Локальные данные

`data/demo.sqlite3` подготовлена заранее; воспроизводимый источник — `data/demo.json`. `arena/data.py` создаёт стандартную БД при её отсутствии и не перезаписывает существующую. GPU, API-ключи и дополнительные pip-пакеты не нужны. Источники фактов записаны в данных: NOAA и официальный Visit Astana; URL во время исполнения не открываются.

Таблицы: concepts, forms, facts, groups, knowledge, metadata. Схема и интерфейсы — в `docs/pipeline/contracts.md`. Адаптер читает прежний формат v0 в пределах имеющихся в нём знаний. Произвольная иная схема требует адаптера. Словарь даёт формы/понятия; новые причинные связи и ситуации требуют соответствующих данных и операций.

Демонстрационные социальные части и персонаж подготовлены с помощью ИИ и требуют проверки/настройки участниками. Они не выдаются за написанный участниками корпус. Готовые LLM в исполняемом решении не используются.

## Проверки

```powershell
python -X utf8 -m unittest discover -s tests -v
python -X utf8 scripts/benchmark.py --count 1000
```

Проверяются контрольная тройка, перефразировки и отрицательные контрпримеры, атрибуция памяти, замена БД, безопасные вычисления, длина, реальное зависание процесса, ошибка доставки и дедлайн. `docs/pipeline/audit.md` хранит первоначальный независимый аудит с найденными проблемами; последующий отчёт о фиксе не заменяет его и не выдаётся за свежий holdout.

Исторический spike лежит в `docs/pipeline/spikes/`, production его не импортирует. Его показатели 16/25 и 0/3 не описывают новую версию. Текущая контрольная тройка проходит 3/3; это ещё не доказательство универсальности или человечности.

## Границы и команда

Покрытие ограничено подготовленными понятиями, отношениями и правилами. Текущая погода, курс валют, чужие личные сведения и расположение ширм неизвестны. Для неизвестного отношения допустимо уточнение/признание незнания. Гарантий победы нет.

YouTube, непрерывная видеозапись и публикация переданы сокоманднику. Наша часть — движок, автономный пакет, время и исходники. Приглашение организатора в приватный репозиторий пока не отправлялось. Сценический протокол передачи ответов требует согласования с организаторами.

Материалы до 26 ноября включительно, онлайн-презентация планируется 27 ноября, готовность к очной секции — к 4 декабря. План, контракты, задачи и состояние находятся в `docs/pipeline/`; требования формы — в `docs/requirements/`.


## Корпус сокомандника: arena v2

`datasets/` содержит неизменённые XLSX из коммита m1tello `3234339`. Это 350 примеров диалогов: 150 со статусом «Подтверждаю» и 200 «Проверить». `data/dialogue.sqlite3` уже подготовлена и автоматически подключается при обычном запуске `python -X utf8 main.py --chat`. Excel, интернет и pip-пакеты во время разговора не нужны. SHA256, листы, исходный коммит и счётчики записаны в `data/corpus_manifest.json`; происхождение каждой записи хранится в SQLite. Метки «Из переписки»/«Новый вариант» перенесены из источника, независимого подтверждения авторства пока нет.

Повторяемый импорт при подготовке новой версии (существующая БД никогда не перезаписывается):

```powershell
python -X utf8 scripts/import_corpus.py datasets --output data/dialogue.next.sqlite3
python -X utf8 main.py --chat --corpus data/dialogue.next.sqlite3
```

«Подтверждаю» использует итоговую колонку «Ответ бота»; «Правка» требует непустой «Твоей правки». «Проверить» и «Убрать» остаются в БД, но исключаются из выдачи. Чтобы добавить следующие 200, сокомандник должен проверить/исправить их в исходной таблице, после чего до испытания нужно повторить импорт и проверку. Во время испытания оператор не меняет данные или ответы.

Смысловые правила, вычисления, действительная память и факты персонажа имеют приоритет. Корпус подбирает ответ для неизвестной бытовой реплики или приветствия: нормализация, ограниченные синонимы/основы, совпадение упорядоченных значимых слов после ограниченных замен и отказ при неоднозначности. Отрицание, участники, числа, время и вид вопроса проверяются отдельно. Контекстные примеры требуют совпадения недавней реплики и её автора; непонятное описание контекста не используется. Новый значимый квалификатор, пропуск смыслового слова или изменение порядка не допускаются: без полноценного разбора такие варианты требуют уточнения. Оценка в диагностике не является вероятностью правильности.

150 подтверждённых примеров не означают 150 активных правил. 35 примеров из тем «Память», «Контекст», «Счёт», «Инструкция», «Предпочтения», «Игра» не используются как статические ответы: среди них есть фиксированные чужие имена, результаты вычислений и несовместимый с текущим персонажем выбор воды вместо чая. Географическая реплика №20 из темы «Игра» также остаётся в карантине. Остальные 115 допускаются к поиску; 5 требуют контекста. Движок может предпочесть существующее правило или уточнение. Тексты подтверждённых ответов сохраняются, включая разговорный стиль и орфографию. Полнота, фактическая правильность всего корпуса и качество на произвольных вопросах этим импортом не доказаны.

Дополнительные команды для разработки:

```powershell
python -X utf8 main.py --ask "Привет, как дела?" --fast --json
python -X utf8 main.py --chat --no-corpus
python -X utf8 scripts/benchmark.py --count 1000 --corpus data/dialogue.sqlite3
python -X utf8 scripts/evaluate_corpus.py
```

Последняя команда проверяет известные примеры, реальные spawn-процессы, контрольную тройку и две выдачи с настоящей задержкой; это регрессия, не слепая оценка. Результат: `evaluations/corpus-v2/integration.json`. В `--json` видны файл, строка и оценка выбранной записи. В обычном режиме выводится только итоговый текст; детали времени идут в stderr.
