# Тьюринг-арена — локальный алгоритмический бот

Текущая версия **arena v3**: Python 3.11, SQLite, только стандартная библиотека. Бот работает локально, без LLM, готовых весов, API и сетевых загрузок. **Ответ выдаётся сразу после вычисления, искусственной задержки нет.**

## Запуск на Windows

Из корня проекта:

```powershell
python -X utf8 main.py --chat
python -X utf8 main.py --ask "Не могу найти ключи, хотя точно принёс их домой"
```

Ответ идёт в stdout; время и статус — в stderr. Для диагностики выбора:

```powershell
python -X utf8 main.py --ask "Привет, как дела?" --json
```

`--fast` оставлен для совместимости прежних команд и больше не нужен. `--seed 42` фиксирует вариативность. `--db PATH` подключает совместимую БД понятий/фактов; `--corpus PATH` выбирает подготовленный корпус; `--no-corpus` запускает только смысловые правила. Новая сессия не наследует память старого процесса.

## Что подключено

Неизменённые исходные XLSX сокомандника находятся в `datasets/`, исходный коммит m1tello — `3234339`. Всего 350 примеров: первичные статусы — 150 «Подтверждаю» и 200 «Проверить». Пользователь отдельно разрешил проверить оставшиеся и подключить прошедшие проверку.

`data/corpus_review.json` содержит по одному решению на каждый пример: **233 accept, 63 rewrite, 54 hold**. Таким образом, в подготовленной `data/dialogue.sqlite3` активны **296 записей**, в том числе **176 из новых 200**. Rewrite включает правки текста или выделение контекста. Это AI-assisted проверка по поручению пользователя, а не заявление о повторном утверждении сокомандниками. Первичные статусы, ответы, контекст и метки происхождения сохранены отдельно в SQLite. Сводка/SHA256 — `data/corpus_manifest.json`; поштучный отчёт — `evaluations/corpus-v3/review-report.md`.

На hold оставлены статические воспоминания с чужими именами, результаты задач, которые должны вычисляться общим алгоритмом, конфликтующие предпочтения, ошибочное географическое утверждение и обещания постоянного формата, которые ещё не поддержаны состоянием. Часть этих запросов обрабатывается существующими общими правилами; наличие исходного примера не заставляет копировать его ответ. Формы самокоррекции имени с вводным «Нет, меня зовут…» и более общий разбор диалога остаются в плане.

## Алгоритм и контекст

Лексическая БД `data/demo.sqlite3` содержит понятия/формы, факты персонажа и смысловые части знаний. Источник для воспроизведения — `data/demo.json`; источники справочных фактов указаны в данных (NOAA, официальный Visit Astana), адреса при ответе не открываются. Демонстрационный персонаж и часть исходных текстов подготовлены с помощью ИИ; метки происхождения таблиц не являются независимо проверенным авторством.

Правила имеют приоритет для вычислений, памяти, персонажа, объяснения радуги, совета о поездке и социальных ситуаций. Корпус расширяет бытовые реакции и приветствия. Сопоставление сохраняет порядок значимых слов после ограниченных замен/основ; отдельно проверяются отрицание, участники, числа, время и тип вопроса. Неподтверждённый новый квалификатор и неоднозначность приводят к уточнению. Диагностическая оценка не является вероятностью правильности.

Проверенные продолжения содержат явные роли user/bot. Они работают только при совпадении недавней истории и авторов реплик. Проверенные пары контекста дают также 28 ответов на начальную реплику: например, «Жду автобус, пешком идти далеко» → «Давно стоишь?» → «О, как раз подъехал» → «О, дождался». Они помечены `kind=context` в trace и сохраняют ссылку на исходную строку. В JSON также видны файл/строка/решение review. Незнакомые формулировки могут не распознаться; универсальность и человечность не заявляются.

## Повторная сборка данных

Excel и дополнительные pip-пакеты не нужны. Подготовка выполняется до испытания; runtime читает только SQLite:

```powershell
python -X utf8 scripts/import_corpus.py datasets --review data/corpus_review.json --output data/dialogue.next.sqlite3
python -X utf8 main.py --chat --corpus data/dialogue.next.sqlite3
```

Существующая БД не перезаписывается. Импорт проверяет точные SHA256 источников, полное покрытие решений, типы/статусы/правки, длину и контекст. При изменении XLSX нужно заново проверить изменённые пары и обновить журнал; старый review не применяется к другим исходникам. Без `--review` импорт сохраняет только исходную политику: «Подтверждаю»/«Правка» активны, «Проверить»/«Убрать» неактивны. Формулы не исполняются.

## Ограничения и проверки

Ответ — русский текст до 300 символов, включая проверку UTF-16. Обработка идёт в отдельном Windows spawn-процессе с лимитом 2 секунды. Сбой, зависание или неправильный результат дают короткий резерв. Память применяется после успешной доставки; повторный request_id не создаёт другой ответ. Для внешнего получателя, который успел принять данные и затем вернул ошибку, нужна собственная идемпотентность/подтверждение.

```powershell
python -X utf8 -m unittest discover -s tests -v
python -X utf8 scripts/benchmark.py --count 1000 --corpus data/dialogue.sqlite3
python -X utf8 scripts/evaluate_reviewed.py
```

Проверки включают настоящий CLI без --fast, короткий/длинный ответ, зависание процесса, контекст/отрицания, исходники/правки, все 350 входов с запретом сетевых вызовов и 28 полных двухходовых прогонов. Последняя команда сохраняет регрессию известных данных в `evaluations/corpus-v3/integration.json`; это не слепая оценка. Фактический финальный ноутбук без сети и доставка на экран конкурса проверяются отдельно командой. Исторические отчёты v1/v2 не переписываются; прежние проверки задержек доступны только через явный внутренний timed=True, обычный CLI их не включает.

План/контракты/задачи — `docs/pipeline/`; требования технической формы — `docs/requirements/`. Исторический spike из `docs/pipeline/spikes/` production не импортирует. YouTube и запись переданы сокоманднику. Доступ организатора в приватный репозиторий и отправка технической формы не выполнялись. Материалы нужны до 26 ноября включительно, онлайн-презентация планируется 27 ноября, готовность к очной секции — к 4 декабря.
