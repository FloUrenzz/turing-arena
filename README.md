# Тьюринг-арена v3

Локальный алгоритмический бот на Python 3.11 и SQLite. Runtime использует стандартную библиотеку, правила и поиск по подготовленным репликам; LLM, обученные веса и внешние API при ответе не используются. Ответ выдаётся после вычисления, без искусственной задержки. Подготовка данных и части кода выполнялась с помощью ИИ.

## Запуск

Заранее установите Python 3.11 и скачайте репозиторий целиком с каталогами `arena`, `data` и `datasets`. Установка пакетов через pip не нужна. После этого бот запускается без подключения к интернету.

Команды выполняются из корня репозитория. Общая база подключается по умолчанию:

```powershell
python -X utf8 main.py --chat
python -X utf8 main.py --ask "Не могу найти ключи, хотя точно принёс их домой"
```

Без `--corpus` CLI выбирает `data/dialogue-combined-5350-v2.sqlite3`. Рядом с ним автоматически подключаются `data/dialogue-expansion.sqlite3` и `data/dialogue-jury.sqlite3`, если они есть. Прежний корпус из 350 исходных примеров (296 активных) доступен через `--corpus data/dialogue.sqlite3`. Явно указанный отсутствующий или невалидный файл вызывает ошибку запуска.

На Windows можно также открыть `scripts/launch_bot.cmd` или выполнить `powershell -File scripts/launch_bot.ps1`. Эти запускатели используют пути относительно репозитория; перенос проекта в другую папку не требует правки путей.

В обычном `--chat` показываются вопросы и ответы. Время и статус включаются флагом `--diagnostics`; при `--ask` они выводятся в stderr автоматически. `--json` показывает структуру ответа, intent, trace и ссылку на выбранную запись:

```powershell
python -X utf8 main.py --ask "Привет, как дела?" --corpus data/dialogue-combined-5350-v2.sqlite3 --json
```

`--no-corpus` оставляет только правила и разговорные реакции. `--db PATH` выбирает совместимую БД понятий и фактов; `--seed 42` фиксирует вариативность. `--fast` сохранён для совместимости и не нужен для быстрого ответа. Новая сессия начинает с пустой памятью.

Бот отвечает на русском языке. Явные клавиатурные последовательности и некоторые длинные случайные наборы букв получают ответ «это ты случайно набрал?», в том числе для распознанного набора латинских букв. Неизвестное имя или иностранное слово сами по себе не считаются случайным текстом.

Для неподдержанных вопросов о составах, учебных темах и философии есть короткие тематические ответы. Они применяются после правил и поиска: уже известные объяснения, вычисления и бытовые реплики сохраняют приоритет.

## Демонстрация контрольных вопросов

Для записи с видимым временем и статусом:

```powershell
python -X utf8 main.py --chat --corpus data/dialogue-combined-5350-v2.sqlite3 --diagnostics
```

Введите по очереди точные вопросы из технической DOCX-формы:

```text
Почему после дождя иногда появляется радуга? Объясни простыми словами.
Что бы ты посоветовал человеку, который впервые приехал в Астану зимой?
Друг опоздал на встречу на полчаса и извинился. Что бы ты ему ответил?
```

`Время до выдачи` измеряет обработку запроса в runtime, включая запуск рабочего процесса. Предварительная загрузка корпуса при старте CLI происходит до этого измерения. Команда запуска сама не отключает сеть компьютера. Порядок демонстрации, требования к непрерывной записи и технической форме описаны в [проверке требований](docs/requirements/technical-check-2026-11-23.md).

## Данные и происхождение

- `data/dialogue-combined-5350-v2.sqlite3` содержит 5350 исходных записей: **5296 активных и 54 hold**. Это прежние 350 примеров и дополнительный набор из 5000. Решения проверки находятся в `data/corpus_review_combined_5350_v2.json`; исходные статусы, ответы и контекст сохранены отдельно от принятых правок.
- `data/demo.json` и создаваемая из него `data/demo.sqlite3` содержат понятия, формы слов, факты персонажа и справочные сведения. Адреса источников, включая NOAA и официальный Visit Astana, записаны в данных и не открываются при ответе.
- В [Excel со всеми репликами](exports/Turing-Arena-v3-все-строки.xlsx) на листе «Все реплики» находятся **10 336 русских строк**: 5296 активных исходных реплик и **5040 проверенных перефразировок**, по одной формулировке на строку. Ещё 54 исходных примера сохранены на отдельном листе «Не используются». У новых вариантов есть собственный ID и ссылка на исходный пример. [JSON с группами вариантов](exports/Turing-Arena-v3-варианты.json) предназначен для программного просмотра.

5040 перефразировок проверены через текущую цепочку ответа и экспортированы для просмотра. Это не 5040 новых физических записей в SQLite: runtime распознаёт варианты по алгоритмам сопоставления и предметным правилам. Excel не загружается при запуске бота.

Расширение доступно как готовая база `data/dialogue-expansion.sqlite3` и [архив из 35 таблиц CSV](exports/Turing-Arena-v3-35-тем.zip). В каждой таблице по 100 000 пар. [Выборка в Excel](exports/Turing-Arena-v3-выборка-100000.xlsx) содержит 100 000 строк из всех тем.

База `data/dialogue-jury.sqlite3` содержит ещё 3 000 000 вариантных запросов. В каждой из трёх групп по 1 000 000 формулировок. Группы охватывают объяснения бытовых явлений, практические советы и реакции в разговоре. Варианты одной ситуации ссылаются на общий ответ. Источники сценариев находятся в `datasets/source-extra/jury_*.py`. Сценарии и варианты подготовлены с помощью ИИ.

Новые примеры, перефразировки, редакторская проверка и демонстрационный персонаж имеют **AI-assisted происхождение**. Первичные файлы команды в `datasets/` и их статусы сохранены; автоматически подготовленные материалы не обозначают независимое авторство или повторное утверждение участниками. Исторические отчёты в `evaluations/corpus-v3/` относятся к прежнему набору из 350 примеров.

Hold не участвует в поиске ответов. Среди таких записей есть статические имена и воспоминания, готовые результаты вычислений, конфликтующие предпочтения и ошибочные утверждения. Некоторые соответствующие запросы обрабатываются общими правилами, а не копированием отложенного ответа.

## Как выбирается ответ

Сначала работают правила для знакомства и памяти, арифметики, персонажа, географии, объяснения радуги, поездок и социальных ситуаций. Затем проверяются точные и ограниченно эквивалентные формулировки корпуса, разговорные продолжения и приблизительный поиск.

При старте `Runtime` строит локальный индекс активных реплик. Приблизительный поиск учитывает формы слов, выбранные синонимы, разговорные сокращения и однозначные небольшие опечатки. Он ищет подходящую существующую запись и сохраняет её источник; новый свободный ответ не генерируется. В JSON-трассировке такой выбор помечен `method=approximate`, точное сопоставление или эквивалентная формулировка — `method=exact-or-paraphrase`.

Дополнительный набор содержит 35 тем по 100 000 пар. Формулировки собраны из базовых ситуаций и разговорных вариантов. Один номер ситуации обозначает группу вариантов с общим ответом. Когда правила и основной корпус не нашли ответ, бот делает запрос по индексу SQLite с учётом регистра, пробелов, `ё` и чатовой пунктуации. Точная реплика из расширения также имеет приоритет перед общим советом про поездку. База читается с диска. В JSON это видно по `method=expansion`.

После пропуска точного поиска расширение сравнивает ключевые слова с базовыми ситуациями и выбирает их тему и ответ. Редкие слова получают больший вес. Для ответа нужны хотя бы два значимых совпадения и достаточно похожий смысл. При близких вариантах из разных тем бот продолжает обычное уточнение. В JSON такой ответ помечен `method=expansion-keywords`.

База для жюри использует отдельный индекс по базовым формулировкам. В JSON у неё указан `corpus=dialogue-jury.sqlite3` и метод `expansion` или `expansion-keywords`. Предметные правила сохраняют приоритет. При неоднозначном совпадении поиск продолжает искать ответ в остальных источниках.

Отрицания, участники разговора, числа, время, важные уточнения и порядок событий проверяются отдельно. Контекстные ответы требуют соответствующей истории с ролями user/bot. Неизвестные значимые слова, конфликтующие близкие ответы и неподдержанные конструкции могут привести к просьбе уточнить. Оценка сходства не является вероятностью правильности, а обработка произвольной человеческой формулировки не гарантируется.

Ответ ограничен 300 символами, в том числе по длине UTF-16. В конце ответа убираются точки, длинные и двойные тире заменяются пробелами. Обработка выполняется в отдельном Windows spawn-процессе с лимитом до 2 секунд; сбой, превышение времени или некорректный результат дают резервную реплику. Состояние диалога обновляется после успешной доставки.

## Пересборка корпуса

Для запуска достаточно готовых SQLite-файлов. Для пересборки нужны исходные XLSX и Python; Excel и сторонние pip-пакеты не требуются. Два первоначальных XLSX лежат в `datasets/`, дополнительный исходник из 5000 строк — в `datasets/source-extra/Turing-Arena-ещё-5000-реплик.xlsx`. Все пути ниже находятся внутри репозитория.

Пересборка по существующему журналу v2 в новый файл:

```powershell
python -X utf8 scripts/import_corpus.py datasets "datasets/source-extra/Turing-Arena-ещё-5000-реплик.xlsx" --review data/corpus_review_combined_5350_v2.json --output data/dialogue-combined-rebuilt.sqlite3
python -X utf8 main.py --chat --corpus data/dialogue-combined-rebuilt.sqlite3
```

Для формирования нового объединённого журнала из прежнего review и исходника на 5000 строк предусмотрен отдельный скрипт:

```powershell
python -X utf8 scripts/build_combined_corpus.py --output data/dialogue-combined-next.sqlite3 --review-output data/corpus_review_combined_next.json
```

Пути результата должны быть новыми: существующие файлы не перезаписываются. Импорт проверяет SHA256 исходников, покрытие решений, контекст и ограничения текста. Если XLSX изменился, старый журнал проверки к нему не применяется. Формулы из XLSX не исполняются. Экспорт «все строки» не заменяет оригиналы для этих команд.

Отдельно можно собрать расширение на 3 500 000 пар из `datasets/source-extra/expansion_*.py`. Команда создаёт SQLite и архив с 35 таблицами CSV. CSV используют UTF-8 с BOM и разделитель `;`.

```powershell
python -X utf8 scripts/build_expansion.py --output local/dialogue-expansion.sqlite3 --archive local/Turing-Arena-35-topics.zip
```

Для подключения поместите собранный `dialogue-expansion.sqlite3` рядом с основной базой в `data` и перезапустите чат. Для сборки нужен свободный диск под базу, архив и временные файлы. В ежедневном запуске архив и исходные сценарии не читаются.

Для уже собранной базы индекс ключевых слов можно добавить отдельно командой `python -X utf8 scripts/index_expansion_keywords.py`. Пересборка CSV для этого не требуется.

Базу для жюри можно пересобрать из исходных сценариев. Если нужно проверить сборку, сохрани результат в новый файл и задай меньшую квоту через `--per-family`. Для подключения в чате имя файла рядом с основной базой должно быть `dialogue-jury.sqlite3`.

```powershell
python -X utf8 scripts/build_jury_corpus.py --output local/dialogue-jury.sqlite3
```

Проверку новых перефразировок можно повторить отдельно:

```powershell
python -X utf8 scripts/generate_paraphrase_variants.py
python -X utf8 scripts/verify_paraphrase_variants.py
```

Кандидаты и отчёты создаются в `local/paraphrases/`; эта рабочая папка исключена из Git. При повторном запуске нужны новые пути (`--output` у генератора, `--directory` и `--export` у проверки) либо явный `--overwrite`. Проверка не изменяет опубликованные файлы в `exports/` и рабочую базу бота. Число принятых вариантов может измениться после изменения алгоритмов или исходных данных; опубликованный экспорт является сохранённым результатом проверки указанной версии.

## Проверки

```powershell
python -X utf8 -m unittest discover -s tests -v
python -X utf8 scripts/benchmark.py --count 1000 --corpus data/dialogue-combined-5350-v2.sqlite3
```

Тесты охватывают правила, память, арифметику, контекст, перефразировки, опечатки, смысловые различия и ограничения runtime. Benchmark измеряет прямые вызовы движка без spawn, поэтому его время не заменяет показания CLI на демонстрации. Генерация кандидатов и проверка перефразировок находятся в `scripts/generate_paraphrase_variants.py` и `scripts/verify_paraphrase_variants.py`; принятие варианта определяется фактическим ответом, отклонённые кандидаты в Excel не включены.

Архитектурные материалы — в `docs/pipeline/`, требования технической формы — в `docs/requirements/`. Исторические spike-скрипты из `docs/pipeline/spikes/` runtime не импортирует.
