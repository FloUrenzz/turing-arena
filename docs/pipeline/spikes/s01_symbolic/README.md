# S-01: первые алгоритмы и маленькая SQLite-БД

Исследовательский прототип, не конкурсная оболочка. Python 3.11, только стандартная библиотека. Данные и правила написаны ИИ для проверки подхода; это не авторский корпус участников конкурса. Сети, весов моделей, загрузок, сторонних библиотек нет.

Из этой папки:

```powershell
python seed.py
python main.py --ask 'Что выберешь: чай или кофе?' --json
python main.py --chat
python main.py --chat --timed --seed 1
python -m unittest -v
```

`--db путь` подключает альтернативную БД с той же схемой. Если БД сокомандника отличается, потребуется явный адаптер: произвольные таблицы автоматически не понимаются. Память одного процесса ограничена 30 репликами; между процессами не сохраняется.

Таблицы `concepts` (лемма, винительный падеж, род, определение), `forms` (известная словоформа → понятие), `facts` (субъект, отношение, объект, степень предпочтения, причина). Демо-формы не являются полной морфологической БД: POS/features пока демонстрационные метки. Нельзя выдавать их за полноценную грамматическую разметку. Содержимое перестраивается `seed.py`, исходная база маленькая и воспроизводимая.

Во второй попытке добавлена таблица `groups`: понятие → категория (напитки, занятия, прослушивание, еда, животные, сезоны). Она позволяет обработать общий вопрос без названия предмета, например выбрать известное предпочтение из категории. Имя и роль извлекаются из `facts`, а не из констант кода. Для точных известных инфинитивов POS=`verb`, остальные записи имеют `unknown`, features=`unannotated`: отсутствующая разметка не имитируется.

Имя и предпочтения собеседника передаются в отложенных `_updates` и применяются только на `commit`. Если перед вопросом собеседник сообщил собственное мнение, простое разделение клауз отделяет его от обращения к боту. Это ограниченная эвристика: кавычки, вложенные предложения, сложная пунктуация и сфера отрицания универсально не разбираются. Сохранение пользовательского утверждения — атрибуция сообщения, не проверка его истинности.

Движок выполняет поиск известных словоформ; выделяет вопросы предпочтения, выбора, причины, определения, идентичности и памяти; использует устойчивые факты персонажа. Отдельные алгоритмы считают ограниченные арифметические выражения через AST и выполняют простые операции над словами. Фраза собирается по общим конструкциям с винительным падежом из БД. Полные вопросно-ответные пары не используются.

Семантика ограничена. Неизвестные предметы, составные вопросы, сложные отрицания, цитаты и несколько субъектов требуют дальнейшей разработки. Удачный ответ на один пример не доказывает универсальное понимание. Новый словарь расширит распознавание форм, но без фактов и правил не даст новых знаний. При недостатке данных возвращается уточнение или признание незнания. В данной версии известный элемент рядом с неизвестным иногда может приводить к неполному разбору — это следует проверять независимыми вопросами.

`Bot.answer` — синхронный тестовый API: готовит и сразу фиксирует ответ. `prepare` и `commit` разделены для CLI, где память обновляется после печати. Тестовый режим работает без задержки. `--timed` использует согласованную формулу `clamp(3 + 0.12 * len(text) + uniform(-1, 1), 3, 40)` от начала вопроса. Он не добавляет паузу сверх времени генерации, однако это не watchdog и не гарантия срока 45 секунд при сбое устройства или зависании движка. Конкурсный интерфейс, изоляция процесса и протокол передачи организатору ещё не реализованы.
