# Сосед по парте — краткое описание проекта

Обновлено: 2026-11-23. Стадия: исследовательский прототип выполнен, план уточняется по результатам и технической форме. Конкурсной реализации ещё нет.

## Замысел

Локальный русскоязычный бот для студенческого конкурса «Тьюринг-арена» строит короткие реплики по собственным правилам. По уточнению пользователя от 2026-11-23 сокомандник отдельно готовит БД слов, а основная работа — алгоритмы разбора вопроса, выбора содержания и грамматической сборки ответа. Содержание берётся из фактов о вымышленном персонаже, причин его предпочтений и памяти раунда. Цель — связный разговор и низкая распознаваемость бота зрителями при соблюдении технических ограничений конкурса. Качество на произвольных вопросах заранее не гарантируется: его проверяем на незнакомых формулировках и в слепой репетиции.

## Подтверждённые сведения

- Заявка отправлена — подтверждено пользователем 2026-11-23.
- Команда: три человека, включая пользователя.
- Пользователь — опытный Python-разработчик.
- Компьютеры команды: Windows, 16 ГБ оперативной памяти.
- Письмо уточняет: DOCX и ссылки до 26 ноября включительно, онлайн-презентация 27 ноября после подтверждения, очная секция 4 декабря в Астане. Общий сайт указывает 4–5 декабря; готовимся к 4-му, расписание уточняем.
- Источник правил: https://itfest.kz/turing-arena/ и текст регламента, присланный пользователем.

## Границы первой версии

Входит: БД лексики; ограниченный разбор русского вопроса; классификация типа вопроса; факты и причины предпочтений персонажа; знания и правила для объяснения, практического совета и социальной реакции из формы; выбор содержания; несколько общих грамматических конструкций; ограниченная память раунда; реакция на незнакомый вопрос; автоматический контроль времени и длины; выдача с задержкой, зависящей от длины и небольшого случайного разброса; локальный интерфейс оператора; диагностический журнал и пакет техпроверки.

Обучение генеративной нейросети, готовые предобученные модели, внешние генераторы, интернет при испытании и универсальный синтаксический разбор русского языка в первую версию не входят. Обработка сложных вопросов ограничена: при недостатке уверенности бот выдаёт короткую уместную реакцию, а не случайную последовательность слов.

## Разделение содержания

1. Лексическая БД — слова, формы, части речи, значения и связи с понятиями. Ответственный: назначенный пользователем сокомандник.
2. Факты персонажа и причины — что персонаж предпочитает, знает и вспоминает. Не выводятся из грамматики слова.
3. Память — что спросили и что бот уже публично ответил в текущем раунде.
4. Правила — как интерпретировать вопрос, выбрать доступный факт и выразить его грамматически.

Один только словарь с леммами не обеспечивает понимание причин, отрицаний и связности диалога. Поэтому словарную часть и содержательную часть проектируем отдельно, со связью через понятия.

## Технологическая основа

Предлагается Python 3.11, SQLite для лексики, локальные файлы для небольшого набора фактов и правил, Tkinter для интерфейса. Для первой версии достаточно стандартной библиотеки; зависимости фиксируются по факту реализации. Схема БД и интерфейсы модулей будут описаны на стадии контрактов, до параллельной разработки компонентов.

В текущей среде проверены Python 3.11.6 и доступность Tkinter/Tcl 8.6.12. Графическое окно и финальный компьютер на этой стадии не проверялись. Python доступен командой `python`; установленный launcher `py` не обнаружил интерпретаторов. Рабочая папка изначально не содержала проекта; репозиторий Git и CI пока не настроены.

## Ограничения и риски

- Не более 45 секунд и 300 символов на ответ. Обычная обработка целится в 1 секунду; к 3 секундам должен быть подготовлен основной или запасной результат. По уточнению пользователя время фактической выдачи зависит от длины: `ограничить(3 + 0.12 × число_символов + случайное(-1, 1), 3, 40)` секунд от начала отсчёта. Вычисление и ожидание входят в общий интервал; их нельзя складывать сверх этого времени. Полный путь до системы показа проверяется на лимит 45 секунд после согласования протокола.
- Бот работает без сети, без предобученных LLM, их весов и внешних API.
- Оператор только вводит исходный вопрос и запускает обработку. Повторный выбор, редактирование результата и управление персонажем во время испытания исключаются из интерфейса.
- Голые слова не дают содержания. Риск закрывается отдельными фактами, причинами и проверкой на новых вопросах до полной реализации.
- Ручная морфология русского языка может разрастись. Первая версия использует ограниченный словарь и только нужные формы; расширение — после измерения качества.
- Отключение устройства и сбой всей ОС не покрываются запасным ответом в программе. Нужны проверка ноутбука, питание и репетиция на финальном оборудовании.
- Используются собственные материалы команды или источники с проверенными правами. Происхождение данных фиксируется без приписывания команде чужого авторства.
- Правила прямо не разъясняют допустимость помощников при подготовке кода и данных. Перед сдачей нужно уточнить применимость требования самостоятельной разработки; нельзя объявлять этот вопрос заранее согласованным. Иллюстрации из чата не считаются написанным участниками корпусом.
- Порядок передачи ответа и отсчёта 45 секунд требуется получить от организаторов; локальное формирование ответа и его получение системой показа — разные этапы.
- По регламенту ответы показывают одновременно. Зритель может не увидеть разницу в длительности подготовки; задержка — пожелание пользователя, а не подтверждённый способ снизить распознаваемость. Она не добавляет паузу поверх общей процедуры одновременного показа.

## Запуск

Запускаемый исследовательский прототип находится в `docs/pipeline/spikes/s01_symbolic/`. В этом каталоге проверены:

```powershell
python -X utf8 main.py --ask "Что выберешь: чай или кофе?" --json
python -X utf8 main.py --chat
python -X utf8 main.py --ask "Почему ты любишь чай?" --timed --seed 42
python -X utf8 -m unittest -v
```

Из корня проекта проверено: `python -X utf8 -m unittest discover -s docs/pipeline/spikes/s01_symbolic -p "test_*.py" -v`. Дополнительных пакетов не требуется. `--db` принимает совместимую SQLite-БД; другой формат требует адаптера. Демонстрационные данные написаны с помощью ИИ и не выдаются за корпус команды. Первый запуск при отсутствии `data/demo.sqlite3` создаёт её из локального seed.

12 unit-проверок проходят; новая независимая проверка показала 16/25 вопросов по заявленным возможностям и 9/10 неизвестных. Общий критерий качества не закрыт; обязательная контрольная тройка ещё не реализована. Полные факты и ограничения — в `spikes/FINDINGS.md`. Это не конкурсная оболочка с watchdog и не доказательство универсальности.
